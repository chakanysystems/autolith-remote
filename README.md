# Autolith for iPad

A native SwiftUI client for Autolith on your Mac, with iPad sidebar navigation, live session status, search, durable conversation history, tool details, message drafts, and create/pause/stop controls. It also supports iPhone. Requires iOS 18 or later.

## Quick start

On the backend host, install Autolith 0.49.0 or newer and configure your provider credentials. Make sure `autolith` is on `PATH`. Install Nix with `nix-command` and `flakes` enabled, and connect the host and your iPhone or iPad to the same Tailscale network.

### 1. Install the bridge

Install into your user profile with [`nix profile add`](https://nix.dev/manual/nix/2.30/command-ref/new-cli/nix3-profile-add.html):

\```sh
nix profile add github:chakanysystems/autolith-remote#autolith-bridge
\```

### 2. Start it

\```sh
autolith-bridge
\```

On first launch, the bridge generates a random companion token and prints its file location. By default, it uses `$HOME/.local/state/autolith-bridge/token`, or `$XDG_STATE_HOME/autolith-bridge/token` when `XDG_STATE_HOME` is set. It reuses the token on later launches. The token file has mode 0600 inside a private mode-0700 directory.

The bridge also creates its separate management credentials and starts Autolith. Leave it running in this terminal. To select a backend executable explicitly, run `AUTOLITH_EXECUTABLE=/absolute/path/to/autolith autolith-bridge`.

### 3. Connect the app

In another terminal, expose the loopback listener through [Tailscale Serve](https://tailscale.com/docs/reference/tailscale-cli/serve):

\```sh
tailscale serve --bg http://127.0.0.1:4318
\```

Copy the HTTPS address printed by Tailscale into the app's server address field. Open the token file at the location printed by the bridge and paste its contents into the app's token field. Connect from the app to view and create sessions.

If you already have a companion token, start with `AUTOLITH_BRIDGE_TOKEN_FILE=/absolute/path/to/token autolith-bridge`. That file must already exist with mode 0600 inside an owned mode-0700 directory.

## Open in Xcode

Open `Autolith.xcodeproj`, select the Autolith scheme, and choose your signing team for both the app and Live Activity targets under Signing & Capabilities. The app bundle identifier is `systems.chakany.autolith-remote`; the extension uses `.liveactivity` as its suffix. Change both identifiers if your team needs its own identifiers.

For command-line device builds, pass `DEVELOPMENT_TEAM=YOUR_TEAM_ID` to `xcodebuild`, or put that setting in an ignored `Local.xcconfig` and pass `-xcconfig Local.xcconfig`. Simulator builds need no signing team.

For the Mac Catalyst app, build for My Mac with automatic signing. `Mac.entitlements` declares the app’s private Keychain access group; sign with a matching Mac Catalyst provisioning profile. For command-line builds on a new Mac, use `-destination 'platform=macOS,variant=Mac Catalyst,arch=arm64' -allowProvisioningUpdates -allowProvisioningDeviceRegistration` to register the Mac and obtain the profile. A build missing Keychain access entitlements fails to save the token with OSStatus `-34018`. See [Apple’s Keychain access-group documentation](https://developer.apple.com/documentation/security/sharing-access-to-keychain-items-among-a-collection-of-apps).

Both shared schemes, `Autolith` and `AutolithActivity`, launch the containing app. The Live Activity extension is embedded automatically and starts through ActivityKit when Show running work is enabled and sessions are working. It has no Home Screen widget descriptor, so launching it with Xcode's autogenerated widget launcher fails with `SBAvocadoDebuggingControllerErrorDomain`. If Xcode retains that old launch configuration, reopen the project and select the shared `Autolith` scheme.

Connect Tailscale on the Mac and iPad. In the app, enter your Mac's Tailscale HTTPS address and the companion token. The token is stored in the device-only Keychain. HTTPS certificate validation is enabled; there are no broad transport-security exceptions.

## Companion bridge

Run the bridge on macOS 14+ or Linux with glibc 2.34+. It uses SwiftNIO for loopback TCP, bounded HTTP/WebSocket parsers, and Swift Crypto on Linux. Run the backend on the same host. For a non-Nix build, install a Swift 5.10-compatible toolchain with Clang and Foundation/Dispatch libraries.
The companion connects to Autolith's HMAC-authenticated management REPL over a private Unix socket. It sends bounded lexical Lisp requests that call session and replay functions. Use Autolith 0.49.0 or newer. Requests with uncertain delivery are never automatically replayed.

Follow the [quick start](#quick-start) for installation and pairing. To build without Nix, run `swift build -c release` and start `.build/release/autolith-bridge`. When copying a SwiftPM build, include `AutolithCompanion_AutolithBridge.bundle` on macOS or `AutolithCompanion_AutolithBridge.resources` on Linux beside the executable.

The bridge creates a separate management token and starts a dedicated Autolith process. It waits up to 30 seconds for an authenticated connection before opening the HTTP listener. The management files are stored in `gateway/` beside the companion token. Keep that directory and `management-endpoints.json` to retain access to running sessions across bridge restarts.

On Ctrl-C, SIGTERM, or SIGHUP, the bridge stops only the gateway process group it started. Sessions created through the app run separately. If the gateway exits, the bridge exits with an error instead of replaying requests or restarting it silently.

Run `tailscale serve --bg http://127.0.0.1:4318`. Keep the existing HTTPS address and companion token in the phone app.

### Use an existing management REPL

Set both `AUTOLITH_MANAGEMENT_REPL_UNIX_SOCKET` and `AUTOLITH_MANAGEMENT_REPL_TOKEN_FILE` to connect to an existing gateway. In this mode, the bridge does not start or stop Autolith. To return to automatic startup, unset both variables.

Management RPC evaluates trusted Lisp with the host user's privileges. Keep its token on the host and separate from the phone-facing token. The bridge starts its gateway with Unix transport, a 60-second evaluation limit, an 8 MiB output limit, and a 32 MiB frame limit.

Live status and durable transcripts refresh through polling. This backend does not install token-streaming hooks or automatically stop idle sessions. Stop remains available explicitly in the app, and saved history remains available for Resume.

The companion binds only `127.0.0.1:4318`. Tailscale Serve supplies private tailnet HTTPS; the companion additionally checks a bearer token. Anyone with both network access and the token can control sessions as the host user. Store provider credentials on the backend host. Rotate the companion token by replacing its file and restarting the companion, then updating the mobile client.

Headers must authenticate within five seconds; authenticated request bodies have fifteen seconds. The bridge reserves separate pending-handshake and authenticated connection capacity. Requests have an overall 65-second deadline, including backend checkout and I/O. Transport failures cancel pending backend work, but a mutation already handed off may have executed. A client may half-close its completed HTTP request and read the response.

### Run with Nix on macOS or Linux

The flake exports `autolith-bridge` as both a package and a command-line app, with default aliases. Supported systems are `aarch64-darwin`, `aarch64-linux`, and `x86_64-linux`. The package builds the Swift bridge with Nix tools. Build the iOS/Mac Catalyst app separately in Xcode.

To run without installing into your profile:

\```sh
nix run github:chakanysystems/autolith-remote#autolith-bridge
\```

From a local checkout, use `nix run .`, `nix build .`, or `nix flake check`. Linux builds run the full Swift test suite. Every build checks startup of the installed executable without injected library paths. Run the macOS suite with Xcode's `swift test`; Nix's Darwin SwiftPM lacks Apple's XCTest runner. `nix build` puts the executable at `result/bin/autolith-bridge`.

`flake.lock` pins the build tools. `Package.swift` and `Package.resolved` pin Swift 5.10-compatible dependencies; `nix/dependencies` contains their fixed hashes and offline SwiftPM workspace metadata. When updating dependencies, resolve the package graph and regenerate that metadata with the pinned `swiftpm2nix`, then test both platforms.

Other flakes can use `inputs.autolith-remote.packages.${system}.autolith-bridge`. The derivation in `nix/package.nix` can also be used with `pkgs.callPackage`. To start the installed bridge at login, use a per-user launchd agent on macOS or systemd user service on Linux. Set `AUTOLITH_EXECUTABLE` in its environment if the backend is not on the service's `PATH`.

## Sessions and permissions

Recent transcripts appear immediately from a protected local cache while the Mac validates their content revision. The cache retains up to 12 conversations, targets 32 MiB in memory, and caps its atomic disk snapshot at 64 MiB. Cache files are excluded from backups and separated by authenticated endpoint. Cached content can be viewed offline; the Mac remains authoritative when connected.

`transcript-sync` hashes the complete decorated history, including read and delivery state. A matching revision returns no message bodies. A known older revision receives changed messages plus the complete authoritative ID order, so edits, deleted messages, reordering, and truncation replace stale history. An unknown revision receives a full replacement. Deleted sessions are removed from memory and disk, and invalidated requests cannot restore them. Reconciliation also runs periodically while native streaming is connected, catching edits made outside the running session.

Visible message read receipts are batched in groups of at most 100. Siri indexing runs after visible content loads and indexes only changed messages in bounded batches. Run the companion and shared client regression checks with `swift test`.

Sessions are grouped by project folder by default, with full paths to distinguish folders sharing a name. Tap a section's disclosure arrow to collapse or expand it. Folders and conversations are ordered by most recent saved activity, newest first. Use the sidebar's Organize sessions menu to switch to All sessions; the choice is saved. Search matches titles and workspace paths and temporarily expands matching folders.

To permanently delete a saved conversation, stop its session first, then swipe left or long-press its sidebar row and choose Delete. Confirming removes its saved history and private attachments from the Mac, keeping workspace files. Active conversations cannot be deleted, including if another client resumes one before deletion completes.

The sidebar shows running sessions, including ones started from the Mac terminal, and saved conversations marked Stopped when no process is running. Their transcripts remain readable, and Resume session starts a new process for the same conversation in Ask mode. Sending a message resumes a paused session and steers an active session. Stop requests graceful shutdown and preserves the saved conversation.

API sessions launch deliberately detached. They do not expect a terminal attachment and are not subject to localgroup's 60-second first-attachment watchdog. A disconnected iPad does not stop them.

New sessions select a Mac workspace and permission mode. **Ask on Mac** requires a controlling terminal for command approvals; without one, Autolith refuses the protected command. **Automatic** uses Autolith's existing permission classifier for unattended work. The session menu can switch between these modes. This client does not impersonate terminal approval dialogs.

Conversation updates show durable messages and tool events, refreshed every two seconds while the app is active. Token-by-token ephemeral output and terminal-only interactive pickers are not transported. In-memory drafts survive changing the selected session. Failed sends keep the draft; mutations are never automatically retried. After a timeout, refresh before retrying, as the Mac may have accepted the operation.

## Native controls

- The model button above the transcript opens a searchable model picker grouped by provider. For sessions created by this companion, choices and completions come from that session's management endpoint. Older sessions without a known management socket use the gateway's configured catalog; their durable history and ordinary controls remain available.
- Enter a parenthesized Lisp expression to run it through Autolith's local input path. Results appear directly in the transcript. Incomplete forms are rejected with the draft preserved. Ordinary local Lisp runs in the active session; `lisp.*` operations retain their disposable-worker behavior.
- Return sends or runs the current input. Shift-Return inserts a newline; Command-Return also sends. Tab accepts the first suggested completion, or tap a suggestion. Completion works at nested forms and avoids strings/comments. Lisp-only results remain local session context until the first prompt persists the conversation, matching the terminal's behavior.
- Command-N starts a session, Command-comma opens Settings, and Command-R refreshes. The sidebar supports pull to refresh. The session menu opens the system share sheet for its loaded transcript.
- Connection, initial history, model loading, mutations, session creation, and running work show contextual progress indicators. Searchable sheets, system materials, Dynamic Type, labeled status, and native sidebar disclosures follow Apple's [iPad guidance](https://developer.apple.com/design/human-interface-guidelines/designing-for-ipados).

For full access to in-memory Lisp results and session-specific completions, stop and resume an older session through the companion once. Updating the companion does not replace an already running Lisp image.

## Live Activities

Turn on **Settings → Live Activities → Show running work**. One Live Activity tracks all working sessions, showing up to three titles plus total sessions, tasks, and queued prompts. Tapping an entry opens that session. The bounded summary also has Dynamic Island layouts on supported iPhones. Idle/stopped sessions do not count as running work; the activity ends when work finishes. A dismissed activity stays dismissed for the current batch while the app remains open.

No Apple push credentials are needed for foreground updates. If the app is suspended or loses its Mac connection, the activity becomes **Update pending** after a minute. It cannot poll Tailscale independently. Mac Catalyst retains the native app controls but does not start ActivityKit activities.

### Optional background updates

Apple requires APNs to update a Live Activity while the app is suspended. The Mac companion already implements token registration, bounded polling, ES256 provider authentication, token expiry/removal, update/end events, and stale dates. This path remains off unless configured. It has not been validated against APNs without a developer key.

When you have an Apple Developer account with push capability for this bundle ID:

1. Enable Push Notifications for the app identifier and its provisioning profile. Build the app with `AUTOLITH_PUSH_ENTITLEMENTS=PushNotifications.entitlements` and `AUTOLITH_PUSH_ENVIRONMENT=development` (or `production` for distribution). Those are Xcode user-defined build settings; the default build needs no push entitlement.
2. Keep the Apple `.p8` signing key on the Mac in an owned, mode-0600 file. Start the companion with these additional environment variables:

   ```sh
   AUTOLITH_APNS_KEY_FILE=/absolute/path/AuthKey.p8
   AUTOLITH_APNS_KEY_ID=your_key_id
   AUTOLITH_APNS_TEAM_ID=your_team_id
   AUTOLITH_APNS_BUNDLE_ID=systems.chakany.autolith-remote
   AUTOLITH_APNS_ENVIRONMENT=sandbox
   ```

   Export these variables in the shell before the normal companion start command. Set `AUTOLITH_APNS_BUNDLE_ID` to your app's bundle identifier if you changed it. Use `production` for a distribution build.
3. Reopen the app and enable Live Activities. The app registers its activity token with your authenticated Mac companion. Titles and counts in the activity are then delivered through Apple's APNs service. Registrations are memory-only and renewed while the app is open, so reopen the app after restarting the daemon. Keys and tokens never enter conversations or VCS.

The implementation uses Apple's [Live Activities guidance](https://developer.apple.com/design/human-interface-guidelines/live-activities) and [ActivityKit push protocol](https://developer.apple.com/documentation/activitykit/starting-and-updating-live-activities-with-activitykit-push-notifications). Apple controls delivery frequency and background execution.

## Siri and Siri AI

Built with Xcode 27. On iOS 27, sessions adopt Apple's `messages.conversation` content schema, with `messages.messagePerson` for the Autolith participant. The entity identity is the connected host plus the durable session ID. Its properties include workspace, status, last activity, and the latest assistant response after the latest user prompt. Status, read, and reply actions exchange this conversation entity. Open uses the system schema. The generic search action is excluded from system discovery because device diagnostics showed Siri routing conversational requests into the sidebar search field. Manual sidebar search remains available.

Conversation content shown in the app or returned through Siri is indexed in a named, complete-protection Spotlight index. The selected view and user activity reference the same entity. Queries reload the current transcript from the Mac; successful refreshes remove indexed conversations that were deleted or belong to a previously connected Mac. Indexing errors appear in Siri settings. Tool output is not included in response content.

On iOS 27 the app also adopts the five messaging action schemas: send, draft, edit sent message, unsend, and set read status. Each conversation has an Autolith recipient scoped to its host and session ID, so a reply can target that conversation. Custom dispatch, progress, read, reply, and stop shortcuts remain available. Existing user-created shortcuts keep their original action identifiers.

Schema sends and notification replies enter a durable Mac outbox with a minimum 15-second delay. Siri can edit or unsend that message before its dispatch deadline, or schedule it for a later date. Draft opens the conversation with editable text. Messaging accepts text prompts; separate subjects, attachments, audio, and locations produce an explicit unsupported-content error. After dispatch starts, edit and unsend fail because executing tools cannot be undone. Requests resume stopped conversations using the original session ID. Unconfirmed delivery is shown in the conversation and is never automatically retried.

The companion stores outbox and read state privately beside its token under `messages/outbox.json`, with one exclusive process owner, synchronized atomic replacement, and crash recovery. Dispatch persists `preparing` before inventory/resume and `dispatching` immediately before sending. Known pre-handoff failures retry after 30, 60, 120, and 240 seconds, then become `failed`. An interrupted or unconfirmed handoff becomes `uncertain` and is never automatically retried. Use Retry for failed delivery or Abandon to remove an unresolved payload while retaining its request-ID tombstone. `message-receipt` queries a request UUID; `message-retry` and `message-abandon` take a session `id` and outbox `eventID`.

Up to 10,000 unresolved messages can wait. Completed payloads are kept for at most 30 days, with a limit of 1,000. Permanent retired request IDs prevent duplicate sends after payload expiry. New admissions and metadata are limited to 24 MiB of serialized state, reserving space for transitions up to a 32 MiB hard limit. A full ledger rejects new work instead of forgetting IDs. Keep the companion running for scheduled messages to dispatch.

New assistant messages start unread. Viewing a message in an active app window, opening its notification, or using a read shortcut records a receipt on the Mac. Read state is shared by devices connected to that companion. Index failures after a confirmed message action are recorded for repair; they do not change the action result. The app requests a current APNs token on each enabled launch and retries failed registration with bounded delays. Equivalent HTTPS address spellings use one host identity.

Changing connections first probes the candidate credentials. Pending callbacks and cached writes are scoped to the captured connection generation. Notification revocation on the old Mac is best effort when it is unreachable; APNs delivery is not exactly once. Local completion notifications provide a fallback. HTTP response accumulation is bounded to 8 MiB for transcripts/message batches, 2 MiB for lists/catalogs/browsing, and 256 KiB for other operations.

Say “Ask Autolith a question” or “Start a task in Autolith”, then dictate your request. In Settings → Siri → Workspaces and nicknames, choose a default Mac folder and add spoken nicknames such as “backend” or “iOS app”. Defaults and nicknames are scoped to the connected Mac. Siri can also resolve these names in the existing “Ask Autolith in [workspace]” phrase.

When the workspace parameter is omitted, the app recognizes explicit references such as “In the backend workspace, investigate the failing tests” and “Investigate the failing tests in backend”. Routing uses folder names and saved nicknames, not a language model. Unknown or multiple matches ask for clarification; requests with no reference use the configured default, or ask if none is configured. An explicit workspace parameter conflicting with the dictated reference requires confirmation. The complete dictation is sent as prose to a new session with ask permissions.

The build enables App Shortcuts Flexible Matching. Registered variations include “Ask Autolith a question” and “Start a task in Autolith”; actual recognition remains Siri-controlled and must be tested on device. Capturing arbitrary free text in the initial invocation sentence is not established. Requests require device authentication and the existing device-only Keychain credential; locked-phone hands-free dispatch is not enabled.

“Read my latest Autolith answer” uses a parameterless iOS 27 action that fetches the conversation most recently sent to on that Mac and returns its current answer as a message entity. Reading an older conversation does not move this last-sent reference. Before the first send with this version, the previously remembered conversation is used. Explicit conversation/workspace read actions remain available separately. The action reports active work and only reads an assistant answer after the latest user question. The legacy read action continues to return text. Spoken answers are limited to 1,200 characters. A failed or unanswered question never falls back to an older answer.

Enable response notifications in Settings. When the app observes work finish during refresh, it posts a local notification with the answer, grouped by conversation. On iOS 27 local alerts identify the corresponding message entity. Tap to open that session or use Reply to enqueue a follow-up in the same conversation. Local notifications require permission and an opportunity for the app to refresh; they cannot keep polling after iOS suspends it.

Suspended-app delivery uses normal APNs alert pushes from the Mac, sharing the APNs configuration described above for Live Activities. It requires an Apple Developer team and provisioning profile that support Push Notifications, an APNs signing key on the Mac, and notification permission. Personal development teams do not support this capability. The default build remains usable without a push entitlement. Registered devices expire after seven days without renewal, and the companion stores registration and completion progress privately in `messages/devices.json`. APNs alerts include conversation routing for tap and Reply; the local alert's App Entity association is not added to remote alerts. CarPlay and spoken announcements remain dependent on system settings and device validation; an acknowledgment does not promise either. Siri AI requires compatible Apple Intelligence hardware and iOS 27; the existing iPad Air 4 supports custom shortcuts but cannot validate Siri AI.

Create a session using **New session → Choose folder…**. The native browser displays folders on the connected Mac, starting at its home directory. Tap folders to navigate, use **Enclosing folder** to go back, and tap **Choose this folder** to select the workspace. Hidden folders and application bundles are omitted. Manual path entry remains available. Folder browsing requires the updated companion and uses the same authenticated connection as session control.

If Siri opens session search instead of asking for a workspace and question, check Settings → Siri → Last action. “Find existing sessions” identifies the search intent; “Dispatch question” identifies the work submission intent. This diagnostic stores the action name and time only. The app refreshes App Shortcut parameters at startup and when the Mac connection becomes available.

Siri follow-ups: “Check Autolith progress” summarizes the default workspace, or all workspaces if none is configured. Add “in [workspace]” to choose one. “Read my Autolith answer in [workspace]” reads the latest session in that workspace; “Read my latest Autolith answer” uses the last conversation asked about or read through Siri. “Stop my Autolith task” uses the default workspace when configured, disambiguates multiple working sessions, and confirms the selected session before sending a stop request. None of these actions needs the private model-delegation API.

Siri conversation follow-ups: say “Follow up with Autolith”, “Continue my Autolith conversation”, or “Reply to Autolith”, then dictate the next question. This sends to the last conversation used by Siri's ask, status, read, or follow-up action on the connected Mac. A stopped conversation is resumed with its original identifier before delivery. Missing conversations, a different returned identifier, and uncertain delivery fail explicitly without creating a replacement conversation or automatically retrying. The Shortcuts action also accepts an explicit session.

New questions and follow-ups explicitly request dictation inside the intent. Settings → Siri → Last action records whether the intent is waiting for dictation, has received it, or has sent it. If Siri answers the question itself while the last action remains waiting, the request did not return to the app's dictation handler. Schema conformance and indexed content provide Siri with conversational context, but actual routing must be validated on a compatible device. Test “Check Autolith progress”, then “What was the latest response?”, then a reply, verifying that all three refer to the same session ID. Explicit Autolith phrases remain a fallback.

Workspace routing recognizes explicit qualified references and leading “In [name], …”, plus known names at the end of “... in [name]”. Ordinary prose such as “How does this work in Rust?” does not trigger workspace clarification unless Rust is a known workspace name. Unknown qualified references still require clarification.

The schema mapping follows [Apple's conversation schema](https://developer.apple.com/documentation/appintents/appschema/messagesentity/conversation), [messaging sample](https://developer.apple.com/documentation/appintents/integrating-your-messaging-app-with-apple-intelligence), and [Spotlight entity guidance](https://developer.apple.com/documentation/appintents/making-app-entities-available-in-spotlight). Schema metadata extraction verifies the declared contract; it does not verify Siri's language routing on device.

Settings → Siri → Siri diagnostics shows the last 100 control-flow events. It records action entry, session-list and transcript outcomes, conversation query callbacks, indexing outcomes, and result preparation. Records contain timestamps, session IDs, counts, response-presence flags, and numeric error codes, with no prompt or response text. Background UI indexing does not fill the trace. A result-prepared event proves execution reached the return boundary; it does not prove Siri consumed or retained that result. After reproducing a routing failure, inspect whether status prepared a result and whether a later conversation query or read action occurred.

Individual user and assistant messages also adopt `messages.message`. Their identities contain the host, session ID, and durable event sequence; their dates come from the record's Unix `timestamp` supplied by the Mac backend. Tool output, replaceable local context records, and undated records are not indexed as messages. Existing transcript clients remain compatible with the additive timestamp field. The client does not fabricate dates when connected to an older backend.

“Read my latest Autolith message” is a separate direct-reading shortcut that returns the actual message entity, including its schema-defined body, author, conversation, and date. It reports working or unanswered conversations without falling back to a previous turn. Message queries resolve existing IDs against the connected Mac, and the named protected Spotlight index supplies semantic lookup. Messages from viewed or Siri-accessed conversations are donated; refreshes remove deleted conversations and invalidated message IDs. The existing conversation-reading shortcut remains available for comparison. Natural follow-up routing requires device validation after installing the messaging action group.

The app refreshes both the viewed conversation and the last Siri-sent conversation while active, so a completed answer can enter Spotlight without opening that session. Message ID lookups refresh the index from the live transcript but still return the exact requested IDs. Diagnostics record returned message IDs, not bodies, to distinguish old-message selection from stale backend content. Siri may still use cached context without calling an action; automatic refresh while suspended is not guaranteed.

Recipient resolution follows the reference app's IntentValueQuery and IntentValueRepresentation pattern: Siri person references resolve back to Autolith recipients, retaining application-defined IDs across renames. Unknown scoped conversation IDs never fall back by name. Unscoped identifiers synthesized by Siri can resolve an exact display-name match, following Apple's sample; duplicate names return all matches for disambiguation. Individual transcript messages expose their own screen annotations. Successful text sends from the app UI donate the corresponding messaging action only after finding the new durable user event; Lisp and local commands are excluded. Siri-originated actions are not donated again.

Schema send acknowledgments validate the returned outbox ID, message body, role, queued state, timestamp, and deadline. Only then does the app return the queued message entity, using the same result shape as Apple's messaging sample. Subsequent indexing failure is recorded without turning accepted delivery into a failure or retry. The returned entity confirms durable queuing, not completed execution. Custom send-result dialog and snippet rendering are disabled while investigating Siri reporting an error after successful delivery.
